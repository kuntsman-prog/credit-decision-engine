# Движок кредитных решений для юридических лиц

[English](README.md) | **Русский**

Учебный, но работающий прототип платформы автоматизированного корпоративного кредитования. Показывает, как устроено принятие кредитного решения: интеграции с бюро кредитных историй и АБС, декларативные правила политики, ML-скоринг с объяснением каждого решения, расчёт лимита, теневой режим новой версии модели, аудит и мониторинг стабильности.

Данные демо вымышленные, модели обучены на синтетическом портфеле. Суммы в долларах США.

## Что демонстрирует проект

| Возможность | Как сделано |
|---|---|
| Интеграция с бюро и АБС | порты и адаптеры, таймауты, повторы, circuit breaker |
| Безопасный отказ | недоступность данных или модели ведёт к ручному рассмотрению, а не к одобрению |
| Правила политики | стоп-факторы и основания для ручного рассмотрения в YAML; ограниченный язык условий без eval, проверка при загрузке |
| ML-скоринг | логистическая регрессия, PD на 12 месяцев, балл скоркарты, рейтинговый класс |
| Объяснимость | вклад каждого признака в решение, основные факторы риска на языке аналитика |
| Лимит | сумма подбирается так, чтобы покрытие платежей (DSCR) было не ниже 1,25 и кредит не превышал 80% залога |
| Champion и challenger | новая версия модели оценивает каждую заявку в теневом режиме и не влияет на решение |
| События | шина с топиками, повторяющими Kafka; сбой подписчика не ломает решение |
| Аудит | хэш входа, версии правил и модели, признаки, причины; ИНН только в виде хэша |
| Мониторинг | PSI по признакам модели |
| Идемпотентность | повторная заявка с тем же идентификатором получает прежнее решение |

Целевая микросервисная архитектура, C4, события и управление модельным риском: [ARCHITECTURE.md](ARCHITECTURE.md).

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m cde.cli decide            # решения по всем демо-заявкам
python -m cde.cli decide A-002      # подробно: признаки, правила, причины, вклад факторов
python -m cde.cli shadow            # сравнение champion и challenger
python -m cde.cli monitor           # стабильность признаков при сдвиге потока заявок
python -m cde.cli train             # переобучить модели на синтетических данных
python -m pytest                    # автотесты

uvicorn cde.app:app --port 8000     # HTTP API: POST /v1/applications, GET /v1/decisions/{id}, GET /health
```

| A-002 | Текстиль Плюс | APPROVE | 1 300 000 из 1 400 000 | 4,5%, C | лимит снижен, чтобы DSCR был не ниже 1,25 |

## Модели

| Модель | Признаки | AUC | Gini | KS | Одобрение | Дефолт среди одобренных |
|---|---|---|---|---|---|---|
| champion pd-corp-1.0 | DSCR, долг к EBITDA, LTV, срок работы, просрочки 30+, выручка | 0,824 | 0,648 | 0,506 | 55,6% | 2,25% |
| challenger pd-corp-1.1 | те же и запросы в бюро за 6 месяцев | 0,830 | 0,660 | 0,522 | 58,1% | 2,24% |

Метрики посчитаны на отложенной выборке из 10 000 заявок; одобрение и дефолт по политике классов без учёта правил.

Теневой прогон на потоке из 5 000 заявок с известным исходом (`python -m cde.cli shadow`):
- решения по классу совпадают в 87,9% случаев;
- 230 заявок одобрила бы только challenger, фактический дефолт по ним 5,7%;
- 114 заявок одобрила бы только champion, фактический дефолт по ним 10,5%;
- дефолт среди одобренных: champion 2,29%, challenger 2,23%.

Новая версия одобряет больше заявок без роста дефолта среди одобренных. Это аргумент для комитета по моделям, а не автоматическое основание для замены.

## Мониторинг стабильности

`python -m cde.cli monitor` имитирует рост ставок: покрытие долга у новых заявителей падает на 25%. PSI по DSCR равен 0,54 (существенный сдвиг, выше 0,25), по остальным признакам меньше 0,01. Такой сигнал означает, что модель нужно перепроверить до того, как изменится фактический дефолт.

## Регулирование

Скоринг юридических лиц не входит в перечень систем ИИ высокого риска EU AI Act: Annex III касается оценки кредитоспособности физических лиц. Если применять движок к индивидуальным предпринимателям или физическим лицам, действуют требования к системам высокого риска. Для банка любая скоринговая модель остаётся объектом управления модельным риском: независимая валидация, мониторинг, документирование. Подробнее в [ARCHITECTURE.md](ARCHITECTURE.md).

## Структура

```
cde/
  models.py        заявка, данные бюро и АБС, решение
  integrations.py  порты и адаптеры, таймауты, повторы, circuit breaker
  features.py      финансовые коэффициенты, аннуитет, обратный расчёт лимита
  rules.py         язык правил, загрузка и проверка, вычисление
  scoring.py       PD, балл скоркарты, класс, вклад признаков
  training.py      синтетический портфель, обучение, метрики, бэктест
  engine.py        поток решения, политика, лимит, аудит, теневой режим
  events.py        шина событий с топиками Kafka
  audit.py         журнал решений
  monitoring.py    PSI
  cli.py, app.py   командная строка и HTTP API
config/rules.yaml    правила кредитной политики
config/policy.yaml   классы, пороги, параметры лимита
models/              champion и challenger с метриками и распределениями
data/fixtures/       демо-заявки, ответы бюро и АБС
tests/               автотесты
```

## Ограничения

Модели обучены на синтетических данных с заданной зависимостью дефолта от признаков; для реальных решений нужны исторические данные банка, независимая валидация и утверждение моделей. Пороги политики и ставка условные.
